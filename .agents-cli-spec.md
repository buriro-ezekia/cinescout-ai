# CineScout AI — project specification

## Purpose

CineScout AI is an evidence-backed pre-production research assistant for filmmakers, producers and screenwriters. It converts production briefs and screenplay extracts into auditable production intelligence while separating external evidence, interpretation, uncertainty and recommendation.

## Tooling

- Google Agent Development Kit (ADK)
- Gemini on Google Cloud / Vertex AI
- Parallel Search MCP
- Agents CLI for local development, evaluation and later deployment support

## Safety and evidence constraints

The system must not invent sources, claim that a matter has been verified without external evidence, or present legal, historical or cultural certainty where the available evidence is insufficient. It must make uncertainty visible and preserve upstream evidence confidence rather than strengthening it during synthesis.

No secrets, access tokens, service-account credentials or local environment files may be committed to the repository.

## Phase 1 vertical slice

Phase 1 proves one complete runtime path before the specialist architecture becomes the default.

Given a production brief or screenplay extract, the Phase 1 system must:

1. identify the factual or contextual matters that require external verification;
2. use Gemini through Google ADK to reason about the brief;
3. invoke Parallel Search MCP at runtime for relevant external evidence;
4. distinguish supported information from uncertainty or conflicting evidence; and
5. return a concise production intelligence response with sources and practical implications.

## Phase 1 acceptance criteria

- The repository contains a valid ADK application with a root agent.
- The root agent has a live Parallel Search MCP toolset configured.
- A user can run the agent locally through Agents CLI after configuring Google credentials.
- When a brief contains externally verifiable claims, the agent is instructed to use Parallel before reaching a factual conclusion.
- The output identifies evidence, uncertainty and production implications.
- Automated tests verify the core configuration and guardrails without making paid external calls.
- No secrets are committed to the repository.

The local Phase 1 baseline and Parallel MCP connectivity are validated. The credentialled Gemini → Parallel runtime proof remains deferred until Google hackathon credits are available for a dedicated CineScout AI project.

## Phase 2 specialist candidate

Phase 2 is additive and must not replace or modify the validated Phase 1 `app/agent.py` entry point before credentialled acceptance.

The candidate uses a deterministic Google ADK graph `Workflow` in this exact order:

1. Brief Interpreter → `phase2_brief_analysis`
2. Research Planner → `phase2_research_plan`
3. Evidence Verifier → `phase2_evidence_review`
4. Production Risk Agent → `phase2_risk_assessment`
5. Report Synthesiser → `phase2_final_report`

The graph is one strict chain from `START` through all five specialists. The Phase 2 production code must not depend on deprecated `SequentialAgent` orchestration.

Every specialist must run as an isolated `single_turn` workflow node with `include_contents="none"`. Only the Evidence Verifier may receive Parallel Search MCP tools. Other specialists must consume explicit shared state rather than conducting their own external research.

The Phase 2 module must export conventional ADK `root_agent` and `app` names so the candidate can be run independently later without replacing the Phase 1 default entry point.

The default bounded research policy is:

- no more than six research tasks unless broader research is explicitly requested;
- no more than one `web_search` call per planned research task; and
- no more than three `web_fetch` calls unless deeper research is explicitly requested.

The final response must retain these sections in order:

- Production reading
- Evidence and verification
- Production implications
- Uncertainty or conflicts
- Sources consulted

## Phase 2 offline acceptance criteria

- A five-stage ADK `Workflow` exists in the exact specialist order above.
- The workflow graph is a strict sequential chain from `START` through all five specialist nodes.
- Every specialist has a distinct output key matching the shared state contract.
- Every specialist is explicitly isolated with `mode="single_turn"` and `include_contents="none"`.
- Specialist factory functions create fresh agent instances for repeated workflow construction.
- Only the Evidence Verifier owns a Parallel MCP toolset.
- The Phase 2 module exports working `root_agent` and `app` aliases.
- Specialist prompts preserve evidence uncertainty and the established response contract.
- The Phase 1 default entry point remains unchanged.
- Local readiness validates the Phase 2 structure with zero Gemini calls and zero external search calls.
- Automated tests verify graph order, state keys, tool ownership, specialist isolation, factory isolation, ADK exports and the at-no-cost execution boundary.
- Phase 2 production code contains no `SequentialAgent` dependency.

The detailed Phase 2 design is maintained in `docs/phase2-spec.md`.

## Deferred Phase 2 live acceptance

Once the intended Google hackathon credits are available, one controlled credentialled run must demonstrate that Gemini executes the five-stage workflow, the Evidence Verifier invokes Parallel Search MCP at runtime, verified evidence reaches the downstream production-risk and synthesis stages, and the final response preserves sources and uncertainty.
